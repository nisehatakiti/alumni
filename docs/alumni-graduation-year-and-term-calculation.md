# 卒業年・期（期生）自動算出設計

## 1. 目的

Alumni Directory および Alumni Core では、卒業生の登録時に卒業年を単なる手入力だけに依存しない。

誕生日から標準的な高校卒業年を自動推定し、同窓会の設定として登録された「第1期生の卒業年」または学校の基準情報から期（期生）も自動算出する。

これにより、名簿登録時の入力負担と卒業年・期の入力ミスを減らす。

## 2. 基本ルール

日本の高校の学年年度区分に合わせ、以下を同一卒業年度グループとして扱う。

```text
4月2日 ～ 翌年4月1日
```

ただし、**誕生日だけでは厳密な卒業年を一意に決定できない**。

浪人・留年・転校・編入・海外在住などの例外があるため、誕生日から算出する値は「標準卒業年の候補」とし、最終的には管理者または本人が確認・修正できる設計とする。

## 3. 標準卒業年の算出

通常の高校卒業（留年なし・標準年齢）を前提とする。

### 4月2日～12月31日生まれ

```text
標準卒業年 = 生年 + 18
```

例：

```text
1978年4月2日生まれ
→ 1996年卒業
```

### 1月1日～4月1日生まれ

```text
標準卒業年 = 生年 + 19
```

例：

```text
1978年4月1日生まれ
→ 1997年卒業
```

### 境界例

```text
1978年4月1日生まれ → 1997年卒
1978年4月2日生まれ → 1996年卒
```

このルールにより、同じ高校学年となる生年月日範囲を扱う。

## 4. 期（期生）の算出

同窓会の設定として、以下のいずれかを基準値として保持する。

### 推奨設定：第1期生卒業年

```text
first_graduation_year = 1965
```

この場合、期は以下で算出する。

```text
term = graduation_year - first_graduation_year + 1
```

例：

```text
第1期生卒業年：1965年

1965年卒 → 第1期
1966年卒 → 第2期
1996年卒 → 第32期
```

## 5. 学校創立年からの設定

学校によっては「創立年」は分かるが、第1期生卒業年がすぐには分からない場合がある。

そのため設定画面では、補助情報として以下を登録可能とする。

```text
school_founded_year
```

ただし、創立年から第1期生卒業年を機械的に算出すると、開校時の学年構成によって誤差が生じる可能性がある。

例えば開校時に新入生のみを受け入れたのか、既存校との統合なのか、2年生・3年生を含む状態で開校したのかによって、第1期卒業年は異なる。

そのため、**期の正式な基準値としては `first_graduation_year` を優先する**。

学校創立年は表示・参考情報として保持する。

## 6. WordPress 同窓会設定画面

Alumni Core に以下の設定画面を設ける。

```text
同窓会設定

学校名
学校創立年
第1期生卒業年

卒業年・期の自動計算
[✓] 誕生日から標準卒業年を提案する
[✓] 卒業年から期を自動計算する
```

第1期生卒業年が未設定の場合、期は自動計算しない。

## 7. Alumni Directory の入力フロー

### 新規登録

管理者が誕生日を入力する。

```text
生年月日
1996 / 05 / 10
```

すると画面上で候補を表示する。

```text
標準卒業年（自動計算）
2014年

期（自動計算）
第XX期
```

管理者はそのまま採用するか、修正できる。

```text
卒業年
[2014 ▼]  ← 編集可能

期
[第XX期]  ← 原則自動計算
```

## 8. ID発行との連携

Alumni ID は卒業年を利用する。

```text
YYYY + 3桁連番
```

例：

```text
1996年卒
1996001
1996002
1996003
```

そのため、ID発行順序は以下とする。

```text
誕生日入力
↓
標準卒業年を提案
↓
管理者が卒業年を確認・修正
↓
卒業年を確定
↓
期を自動算出
↓
member_id を発行
```

**member_id は卒業年確定後に発行する。**

誕生日から自動提案された値だけで即時発行しない。

## 9. 卒業年変更時のルール

誤登録により卒業年を変更する場合、既存の member_id を変更するかどうかは重要な設計判断となる。

推奨ルール：

```text
内部 id        → 不変
member_id      → 原則不変
卒業年         → 修正可能
```

例：

```text
member_id = 1996001
卒業年 = 1996
```

が、実際には1997年卒だった場合：

```text
member_id = 1996001（維持）
卒業年 = 1997（修正）
期 = 再計算
```

member_id は発行後の外部参照キーとして扱い、卒業年修正によって自動変更しない。

必要であれば将来、`graduation_year_at_issue` を監査用に保持する。

## 10. 例外対応

以下のケースでは誕生日から算出した標準卒業年と実際の卒業年が異なる可能性がある。

- 留年
- 飛び級等の特殊ケース
- 転校・編入
- 海外からの編入
- 高校を卒業していない
- 既存名簿の卒業年表記と実際の年度の違い

したがって、卒業年は必ず編集可能とする。

誕生日は「入力支援」、卒業年は「確定情報」として扱う。

## 11. 推奨DB項目

Alumni Core の卒業生テーブルには少なくとも以下を持つ。

```text
id                         BIGINT UNSIGNED AUTO_INCREMENT
member_id                  VARCHAR(16) UNIQUE
birth_date                 DATE NULL
graduation_year            SMALLINT UNSIGNED NULL
graduation_term            INT UNSIGNED NULL
```

設定テーブルまたは WordPress options には以下を持つ。

```text
school_name
school_founded_year
first_graduation_year
```

## 12. 設計原則

1. 誕生日は卒業年を自動確定する情報ではなく、入力支援に利用する。
2. 卒業年は最終的に管理者が確認できる。
3. 期は確定した卒業年から自動計算する。
4. 期の基準は第1期生卒業年を優先する。
5. member_id は卒業年確定後に発行する。
6. 誤登録修正で member_id を安易に変更しない。
