# Alumni Directory（名簿管理）管理画面設計

## 1. 目的

Alumni Directory は、Alumni Core が管理する共通の卒業生データベースを WordPress 管理画面から安全かつ継続的に登録・検索・更新するための管理プラグインである。

Alumni Voices は卒業生自身から情報を集める入口だが、名簿管理は Alumni Voices に依存しない。管理者は WordPress 管理画面から直接、卒業生情報を追加・修正・検索できる。

## 2. プラグインの責務

- 卒業生の新規登録
- 卒業生情報の検索・一覧
- 基本情報の編集
- メールアドレスの複数管理
- 部活動の複数登録
- クラス履歴の登録
- 情報登録元・更新履歴の確認
- CSVインポート／エクスポート（Phase 2）

Alumni Directory は DB テーブルを直接作成しない。Alumni Core の API / Repository を通じてデータを操作する。

## 3. WordPress 管理メニュー

管理画面のメニュー構成は以下とする。

```
同窓会名簿
├── 卒業生一覧
├── 新規登録
├── 部活動管理
├── インポート（Phase 2）
├── エクスポート（Phase 2）
└── 設定
```

WordPress 標準の投稿画面に無理に混在させず、独立した管理メニューとする。

## 4. 卒業生一覧画面

### 表示項目

- 氏名
- 卒業年
- 期
- 主メールアドレス
- 部活動
- 登録元
- 最終更新日
- ステータス

### 検索条件

- 氏名
- メールアドレス
- 卒業年
- 期
- クラス
- 部活動
- 登録元
- メール配信可否

複数条件を同時指定できる。

### 操作

- 詳細表示
- 編集
- 新規登録
- アーカイブ

原則として物理削除ではなくアーカイブ（論理削除）を使用する。

## 5. 新規登録・編集画面

### A. 基本情報

```
姓
名
姓（ふりがな）
名（ふりがな）
卒業年
期
在籍状況
備考
```

氏名変更に備え、将来的に旧姓等を扱える拡張余地を残す。

### B. メールアドレス

1人につき複数登録可能とする。

```
メールアドレス
主メールアドレス
確認済み
配信可
ステータス
```

「メールを追加」ボタンで行を増やせる UI とする。

### C. 部活動

複数選択可能。

```
[野球部] ×
[軽音楽部] ×

+ 部活動を追加
```

検索可能なセレクトボックスを使用し、同じ部活動の重複登録を禁止する。

必要に応じて所属開始年・終了年・役職・備考も編集できる。

### D. クラス履歴

学年ごとに複数行管理する。

```
学年 | 学級 | 年度
1年  | 3組  | 1990
2年  | 5組  | 1991
3年  | 2組  | 1992
```

「クラスを追加」で行を追加できる。

### E. データ履歴

画面下部に以下を表示する。

- 初回登録日
- 登録元
- 最終更新日
- 最終更新者
- Alumni Voices 由来の場合は対象 WordPress 投稿へのリンク

## 6. 重複チェック

名簿管理では重複登録を重要な課題として扱う。

新規登録時に以下をチェックする。

1. 同一メールアドレス
2. 氏名＋卒業年
3. 氏名＋卒業年＋クラス

完全一致があった場合は新規登録を即時拒否せず、既存候補を表示する。

```
類似する卒業生が見つかりました

・山田 太郎（2001年卒）
・山田 太郎（2002年卒）

既存情報を編集する / 新規登録を続行する
```

## 7. アーカイブと削除

通常操作では物理削除しない。

```
active
archived
```

を卒業生レコードに持つ。

アーカイブされた卒業生は通常検索・通常配信対象から除外するが、管理者は履歴確認できる。

完全削除は将来的な個人情報削除要求等の専用フローとして扱う。

## 8. 権限設計

### alumni_directory_view
名簿閲覧

### alumni_directory_edit
卒業生情報の編集

### alumni_directory_export
CSV等のエクスポート

### alumni_directory_delete
完全削除等の高権限操作

WordPress 標準 role ではなく capability を基準に判定する。

## 9. データ操作ルール

Alumni Directory は `$wpdb` で直接 SQL を記述して各テーブルを自由に更新しない。

必ず Alumni Core の API を利用する。

概念例：

```php
Alumni_Core::create_alumnus( $data );
Alumni_Core::update_alumnus( $alumni_id, $data );
Alumni_Core::add_email( $alumni_id, $email );
Alumni_Core::set_clubs( $alumni_id, $club_ids );
Alumni_Core::set_class_memberships( $alumni_id, $classes );
```

これにより、Alumni Voices、Alumni Directory、Alumni Mail が同じデータ整合性ルールを共有できる。

## 10. CSVインポート（Phase 2）

既存同窓会名簿の移行を想定する。

手順：

1. CSVアップロード
2. 列マッピング
3. プレビュー
4. 重複候補表示
5. 登録対象確認
6. インポート実行
7. 結果レポート

既存データを一括で上書きしない。

## 11. CSVエクスポート（Phase 2）

エクスポート対象は権限を持つ管理者のみとする。

メールアドレスを含む個人情報のため、ダウンロード履歴を将来的に監査ログへ記録できる設計とする。

## 12. 画面フロー

## 15. 設計原則

Alumni Directory は単なる名簿閲覧画面ではない。

**Alumni Core に蓄積された卒業生データを、人間が継続的に育て、整備するための管理コンソール**として設計する。

卒業生自身からの情報収集は Alumni Voices 等が担当し、管理者による修正・統合・整理は Alumni Directory が担当する。メール配信は Alumni Mail が担当する。この責務分離を維持する。
