# トップページ・スロット配置とナビゲーション連動設計

## 1. 設計方針

トップページは、テーマ側であらかじめデザインされたレイアウト（配置スロット）を持つ。

各スロットに、利用可能なコンテンツを管理画面から割り当てる。

さらに、割り当てられたコンテンツをもとに、上部グローバルメニューを自動生成・連動できるようにする。

目的は、広報担当者がトップページの構成を変更した際に、メニューの追加・削除・リンク修正を別作業として行わなくても済むようにすることである。

---

## 2. レイアウトとコンテンツの分離

テーマ側はコンテンツ名ではなく、スロット構造を定義する。

例：

```text
┌──────────────────────┐
│         HERO         │
└──────────────────────┘

┌──────────┬──────────┐
│    A     │    B     │
└──────────┴──────────┘

┌──────────────────────┐
│          C           │
└──────────────────────┘
```

管理者は各スロットにコンテンツを割り当てる。

```text
A：会長挨拶
B：校長挨拶
C：母校ニュース
```

別の導入先では、同じレイアウトに対して以下のような割り当ても可能とする。

```text
A：Alumni Voices
B：Teacher's Voice
C：同窓会ニュース
```

---

## 3. グローバルメニュー連動

各コンテンツは、トップページへの配置とは別にナビゲーション設定を持つ。

ただし、トップページのスロットにコンテンツを割り当てた場合、メニュー設定は初期状態で自動連動する。

### 初期動作

```text
Aスロット
表示コンテンツ：Alumni Voices
```

を選択すると、ナビゲーション候補として自動的に以下を設定する。

```text
表示：ON
表示名：卒業生からの声
リンク先：Alumni Voicesの一覧ページ
```

管理者が必要に応じて変更できる。

---

## 4. ナビゲーション設定

各コンテンツについて以下を設定可能とする。

```text
上部メニューに表示する：ON / OFF

表示名：自由変更可能

リンク先：コンテンツの正式URLを自動設定

表示順：管理可能
```

これにより以下の運用を可能にする。

### ケースA

```text
トップページ：ON
メニュー：ON
```

### ケースB

```text
トップページ：ON
メニュー：OFF
```

### ケースC

```text
トップページ：OFF
メニュー：ON
```

---

## 5. コンテンツ変更時の動作

例えばAスロットを以下のように変更する。

```text
Alumni Voices
↓
Teacher's Voice
```

ナビゲーションが自動連動モードの場合、メニュー候補も以下のように更新する。

```text
卒業生からの声
↓
先生からの声
```

リンク先も新しいコンテンツの正式URLに自動変更する。

ただし、管理者がメニュー名やリンクを個別に固定・編集した場合は、その設定を尊重する。

---

## 6. 管理画面イメージ

```text
[A] スロット

表示コンテンツ
▼ Alumni Voices

────────────────

ナビゲーション

☑ 上部メニューに表示する

表示名
[ 卒業生からの声            ]

リンク先
[ 自動設定                   ]

表示順
[ 5 ]
```

---

## 7. 設計原則

この仕組みでは、広報担当者がサイト構成を設定するだけで、トップページと上部ナビゲーションの整合性を保てることを重視する。

```text
コンテンツを選ぶ
↓
トップページに配置される
↓
必要に応じてメニューにも自動反映される
```

「トップページだけ変更してメニューを修正し忘れる」という運用ミスを減らす。

---

## 8. 確定事項

トップページは「デザインされた配置スロット」にコンテンツを割り当てる方式とする。

グローバルメニューは、スロットに割り当てられたコンテンツと初期状態で連動し、表示名・表示有無・順序については管理者が調整できるものとする。

コンテンツデータはプラグイン側、配置・ナビゲーションの見せ方はテーマ側で管理する。
