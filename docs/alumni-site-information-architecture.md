# Alumni サイト情報設計

## 1. 目的

Alumniサイトのコンテンツを「誰に向けた情報か」「サイト上でどの階層に属するか」「どのようにメニューや公開画面へ現れるか」という観点で整理する。

この文書は、Alumni Coreを利用して構築するサイト全体の情報設計に関する基本仕様とする。

## 2. 基本原則

Alumni Coreはコンテンツそのものと、その公開上の構造を管理する。

Themeは同じデータを利用して、レイアウトとナビゲーションの見せ方を変更する。

```text
Alumni Core
  ├── コンテンツ
  ├── 対象者カテゴリ
  ├── コンテンツ階層
  ├── 公開状態
  └── メニュー表示設定
          ↓
       Theme
          ↓
  左サイド型 / トップメニュー型 等
```

## 3. 大カテゴリ

最上位の対象者カテゴリとして、以下を基本とする。

- 卒業生向け
- 在校生向け
- 共通

「在校生向け」は学校が発信する情報ではなく、**同窓会が在校生に向けて発信する情報**を意味する。

例：

```text
在校生向け
└── Alumni-Voices
```

学校行事や学校公式のお知らせ等、学校側が主体となる情報はAlumni Coreの対象範囲に含めない。

## 4. コンテンツ階層

大カテゴリの下では、コンテンツを親・子・孫の任意階層で構造化できるようにする。

例：

```text
卒業生向け
└── 同窓会情報
    ├── 会長挨拶
    ├── 同窓会組織図
    │   └── 理事・役員一覧
    └── 同窓会規約
        ├── ○○規約
        └── ××規約
```

別例：

```text
在校生向け
└── Alumni-Voices
    ├── 卒業生からのメッセージ
    ├── 社会人インタビュー
    └── 卒業生の仕事紹介
```

## 5. 自由入力ページ

自由入力ページも特殊扱いせず、他のコンテンツと同じサイト構造へ参加できるようにする。

管理時に、

- 対象者カテゴリ
- 親コンテンツ
- 公開状態
- メニュー表示
- 表示名

を設定できるようにする。

例えば「卒業生インタビュー」という自由入力ページを「在校生向け ＞ Alumni-Voices」に紐付ければ、その階層がメニュー・パンくず・関連ページ等の公開構造へ反映される。

## 6. コンテンツ種別とサイト階層は分離する

以下のコンテンツ種別は、それぞれ必要なデータ構造を持つが、サイト階層上では共通の仕組みに参加できるようにする。

- 自由入力ページ
- 人物挨拶
- ニュース
- イベント
- 規約類
- 役員・理事一覧
- 卒業期早見表
- Alumni-Voices等の将来プラグインコンテンツ

「コンテンツ種別」と「どこに表示するか」を同一概念にしない。

## 7. メニュー生成

メニューは固定HTMLを前提とせず、Alumni Coreで有効化された公開コンテンツと、その階層から生成できる構造とする。

ただし、公開されているコンテンツを必ずメニューへ出す必要はない。

コンテンツ単位で、少なくとも以下を設定できるようにする。

```text
公開：ON / OFF
メニュー表示：ON / OFF
表示名：自由設定
表示順：管理可能
```

親コンテンツに子コンテンツが存在する場合、Themeはそれをドロップダウン、サイドメニュー、アコーディオン等の適切なUIへ変換する。

## 8. 想定サイト構造

```text
卒業生向け
├── 同窓会情報
│   ├── 会長挨拶
│   ├── 同窓会組織図
│   │   └── 理事・役員一覧
│   ├── 同窓会規約
│   │   ├── ○○規約
│   │   └── ××規約
│   └── 卒業期早見表
├── ニュース
└── イベント

在校生向け
└── Alumni-Voices
    ├── 卒業生からのメッセージ
    └── 社会人インタビュー
```

これは初期データ例であり、導入先ごとに自由に変更できる。

## 9. トップページとの関係

サイト階層とトップページ上の配置は別概念として管理する。

例えば、

```text
サイト階層
卒業生向け ＞ 同窓会情報 ＞ 会長挨拶
```

であっても、トップページでは、

```text
メッセージセクション ＞ 1段目
```

へ表示できる。

同じコンテンツをサイト階層の変更なしにトップページ上の別の場所へ配置できる。

## 10. Themeの責務

Themeは、Coreから提供された構造を視覚的に表現する。

初期テーマとして以下を想定する。

### Formal / Side Navigation

- 左サイドメニュー
- 階層を明示的に表示
- 学校・同窓会向けのフォーマルな見た目

### Simple / Top Navigation

- 上部メニュー
- ドロップダウン等で下位階層を表示
- シンプルで現代的な見た目

Theme変更によってCoreのコンテンツデータや階層を失わない。

## 11. 管理画面の原則

管理者がHTMLやURLを直接編集しなくても、

```text
大カテゴリを選ぶ
↓
親コンテンツを選ぶ
↓
コンテンツを登録
↓
公開／メニュー表示を設定
```

という操作で公開構造が完成することを目指す。

親コンテンツの選択は、長大な一覧から探すのではなく、階層を辿るドリルダウンUIを優先する。

## 12. 将来拡張

この情報設計を維持することで、将来以下のコンテンツを追加しても同じ構造へ参加できる。

- Alumni-Voices
- Teacher's Voice
- 同窓会活動報告
- 会報
- キャリア情報
- 同期会・OB/OG会情報
- その他の同窓会発信コンテンツ

新しいコンテンツ種別を追加しても、サイト全体のメニュー構造を作り直す必要がないことを目標とする。

## 13. 最終原則

> 「何を表示するか」と「どこに属するか」と「どう見せるか」を分離する。

Alumni Coreが情報と構造を持ち、Themeがその構造を適切なUIへ変換する。
