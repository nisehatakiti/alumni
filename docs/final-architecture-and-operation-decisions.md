# 偽秦高等学校同窓会サイト 最終アーキテクチャ・運用方針

## 1. プラグイン構成

プラグインは以下の構成を基本とする。

```text
Alumni Core
├ 共通設定
├ 名簿共通DB
├ 卒業年・卒業期計算
├ 共通データアクセス
└ 他プラグイン共通機能

Alumni Voices
└ 卒業生からの声

Alumni Directory
└ 名簿管理

Alumni Newsletter
└ メールマガジン

Alumni Content / 個別機能群
├ Teacher's Voice
├ 沿革
├ 校歌
├ 組織・役員
└ その他専用コンテンツ

Alumni Theme
├ トップページ
├ コンテンツ配置
├ ナビゲーション
└ 表示デザイン
```

CoreとThemeについては、それぞれ共通基盤・表示基盤としてまとまった構成とする。

それ以外の主要機能は独立したプラグインとして構成する。

## 3. 個人情報・公開方針

名簿に登録する個人情報は原則として完全非公開とする。

公開サイト上で個人情報を一覧表示することはしない。

### Alumni Voicesの公開名

投稿者は公開方法として以下を選択できる。

- 実名
- イニシャル
- 匿名

管理者は投稿内容を確認してから公開する。

メールアドレス、生年月日等の名簿情報は公開しない。

---

## 4. メールマガジン登録・停止運用

名簿データにはメールマガジン配信可否フラグを保持する。

例：

```text
newsletter_enabled = true / false
```

メールマガジンへの新規登録、メールアドレス変更、配信停止等については、MVPでは利用者向けの自動変更画面を設けない。

利用者は管理者へ連絡し、管理者が名簿管理画面から手動で変更する運用とする。

対象人数が限定的な同窓会運用では、この方式で十分と判断する。

---

## 5. 定期処理

プラグインの定期処理はWordPress Cron（WP-Cron）を利用する。

対象例：

- メール配信キュー処理
- 定期リマインド
- 投稿情報の定期確認
- その他の自動処理

MVPではサーバー固有のCron設定を必須としない。

WordPressプラグインとして導入しやすいことを優先し、WP-Cronを標準方式とする。

---

## 6. 確定事項

以下を最終方針として確定する。

1. CoreとThemeは共通基盤としてまとめる。
2. Alumni Voices、Directory、Newsletter等は独立プラグインとして構成する。
3. 個人情報は原則完全非公開とする。
4. Alumni Voicesでは実名・イニシャル・匿名を投稿者が選択できる。
5. 名簿にメールマガジン配信可否フラグを保持する。
6. メールアドレス変更・配信登録変更はMVPでは管理者が手動対応する。
7. 定期処理はWordPress Cronを標準とする。
