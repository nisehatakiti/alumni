# トップページ：スロットベースのレイアウト設計

## 1. 方針

トップページは、個別コンテンツの組み合わせをテーマに固定するのではなく、テーマが定義した「セクション／配置スロット」に対して、管理者が表示するコンテンツを選択する方式とする。

コンテンツそのもの、サイト構造、トップページ上の配置、テーマによる見せ方を分離する。

```text
Alumni Core
  ├── コンテンツそのもの
  ├── 対象者カテゴリ
  ├── コンテンツ階層
  └── 公開／メニュー設定

Theme
  ├── ページの見た目
  ├── ナビゲーションの表示方法
  └── トップページのレイアウト定義

トップページ設定
  └── 各セクションのレイアウトと表示コンテンツを選択
```

---

## 2. テーマは複数種類を提供する

同じAlumni Coreのコンテンツを、複数のThemeで表示できるようにする。

初期の代表テーマは以下を想定する。

### Formal / Side Navigation

左サイドにメニューを配置する、学校・同窓会向けの比較的フォーマルなデザイン。

```text
┌────────────────────────────────┐
│            Header              │
├────────────┬───────────────────┤
│ Navigation │      Content      │
│            │                   │
│            │                   │
└────────────┴───────────────────┘
```

### Simple / Top Navigation

上部にメニューを配置する、シンプルで現代的なデザイン。

```text
┌────────────────────────────────┐
│ Header                         │
│ HOME | 卒業生向け | 在校生向け │
├────────────────────────────────┤
│            Content             │
└────────────────────────────────┘
```

Themeを変更しても、Alumni Coreに保存されたコンテンツやサイト構造は失わない。

---

## 3. 大カテゴリ（対象者カテゴリ）

サイト構造の最上位には、情報の対象者を表す大カテゴリを持たせる。

初期カテゴリ：

- 卒業生向け
- 在校生向け
- 共通

ここでいう「在校生向け」は、学校から発信する情報ではなく、**同窓会が在校生に向けて発信する情報**を意味する。

例えば在校生向けには以下を配置できる。

```text
在校生向け
├── Alumni-Voices
├── 同窓会からのお知らせ
└── その他の在校生向けコンテンツ
```

学校行事など学校側が管理・発信する情報は、Alumni Coreの対象範囲には含めない。

---

## 4. コンテンツの階層

コンテンツは大カテゴリの下で、親・子・孫という任意の階層を持てるようにする。

例えば：

```text
卒業生向け
└── 同窓会情報
    ├── 会長挨拶
    ├── 同窓会組織図
    │   └── 理事・役員一覧
    └── 同窓会規約
        ├── ○○規約
        └── ××規約
```

別の例：

```text
在校生向け
└── Alumni-Voices
    ├── 卒業生からのメッセージ
    ├── 社会人インタビュー
    └── 卒業生の仕事紹介
```

### 階層の意味

この階層は単なる表示上の装飾ではなく、以下の情報構造として利用する。

- メニューの階層
- ページ間の親子関係
- パンくず等のナビゲーション
- トップページのコンテンツ選択UI
- コンテンツ一覧の分類

管理者がコンテンツをどの親に紐付けるかを変更すると、メニューや関連する公開画面の構造も変更される。

### 階層とコンテンツ種別の分離

自由入力ページ、人物挨拶、ニュース、イベント、規約類、役員一覧等は、それぞれのデータ構造を持つが、サイト上の階層には共通して参加できるようにする。

「自由入力ページだから特別な階層を持てない」という制約を設けない。

---

## 5. コンテンツの公開とメニュー

Alumni Coreで登録されたコンテンツは、対象者カテゴリと階層を基準に公開構造へ参加する。

ただし、すべてを必ずメニュー表示する必要はない。

コンテンツごとに、少なくとも以下を設定できるようにする。

```text
公開：ON / OFF
メニュー表示：ON / OFF
表示名：自由設定
表示順：管理可能
```

「公開されているがメニューには出さない」コンテンツも許容する。

「トップページには表示するがメニューには表示しない」等の使い分けも可能とする。

---

## 6. ナビゲーション構造

ナビゲーションは固定HTMLではなく、Alumni Coreの有効なコンテンツと階層から生成できる構造とする。

例：

```text
卒業生向け
├── 同窓会情報
│   ├── 会長挨拶
│   ├── 同窓会組織図
│   │   └── 理事・役員一覧
│   └── 同窓会規約
│       ├── ○○規約
│       └── ××規約
└── Alumni-Voices

在校生向け
├── Alumni-Voices
└── 同窓会からのお知らせ
```

Themeはこの構造を、左サイドメニューまたはトップメニュー等の適切なUIへ変換する。

---

## 7. トップページは「セクション」単位で構成する

トップページは複数のセクションから構成する。

各セクションについて、管理者が以下を設定する。

```text
セクション表示：ON / OFF
セクション見出し：任意
レイアウト：1段 / 2段 / 3段 / その他Themeが提供する定型レイアウト
各段に表示するコンテンツ：選択式
表示順：セクション単位で管理
```

「トップページ全体を自由にHTMLで組み立てる」のではなく、Themeが用意した定型レイアウトを選択して、その中身をCoreのコンテンツから選ぶ。

---

## 8. 横3段レイアウトの具体例

例えば「横3段」を選択すると、管理画面で各段のコンテンツを選択できる。

```text
セクション：メッセージ
レイアウト：横3段

1段目：会長挨拶
2段目：校長挨拶
3段目：卒業生の声
```

公開画面：

```text
┌──────────┬──────────┬──────────┐
│ 会長挨拶 │ 校長挨拶 │ 卒業生の声 │
└──────────┴──────────┴──────────┘
```

同じ3段レイアウトでも、別の導入先では、

```text
1段目：Alumni-Voices
2段目：同窓会ニュース
3段目：イベント
```

のように変更できる。

---

## 9. コンテンツ選択UIはドリルダウン方式

各段に表示するコンテンツは、登録済みコンテンツをドリルダウンして選択できるようにする。

例：

```text
表示コンテンツを選択

卒業生向け
  └ 同窓会情報
      └ 挨拶
          └ 会長挨拶
```

または、

```text
卒業生向け
  └ Alumni-Voices
      └ 卒業生からのメッセージ
```

大量のコンテンツを1つの長大なセレクトボックスに並べるのではなく、階層を辿って選択できるUIを優先する。

選択時にはコンテンツの種類も識別できるようにする。

---

## 10. セクションの組み合わせ

セクションは複数追加できる。

例えば：

```text
トップページ

[Section 1]
レイアウト：1段
コンテンツ：メインメッセージ

[Section 2]
レイアウト：3段
会長挨拶｜校長挨拶｜卒業生の声

[Section 3]
レイアウト：2段
ニュース｜イベント

[Section 4]
レイアウト：1段
学校写真
```

セクションの順序を変更することでトップページ全体の構成を変更できる。

---

## 11. コンテンツとトップページ配置の分離

同じコンテンツを、サイト階層上の1箇所に登録しながら、トップページ上では別の場所に配置できる。

例えば、

```text
サイト階層：
卒業生向け ＞ 同窓会情報 ＞ 会長挨拶
```

であっても、トップページでは、

```text
メッセージセクション ＞ 1段目
```

に表示できる。

したがって、

**サイト階層とトップページ配置は別概念として保持する。**

---

## 12. Themeとトップページ設定の責務

Themeは「どのようなレイアウトを提供できるか」を定義する。

トップページ設定は「そのレイアウトに何を表示するか」を管理する。

```text
Theme
  └── 1段、2段、3段、Hero等のレイアウト定義

Alumni Core / Site Configuration
  └── 各セクションのレイアウト選択
  └── 各スロットのコンテンツ選択
```

Themeを変更しても、可能な限りコンテンツ選択情報を保持する。

ただし、新しいThemeに存在しないレイアウトを利用している場合は、管理者に未対応設定として分かるようにする。

---

## 13. 完全自由なページビルダーにはしない

以下はMVPでは採用しない。

```text
× 任意位置へのピクセル単位配置
× HTML直接編集を前提としたページ作成
× ドラッグ＆ドロップだけで完全自由なレイアウト構築
```

代わりに、

```text
○ Themeが提供する定型レイアウト
○ セクション単位の追加・並び替え
○ 各段へのコンテンツ選択
○ コンテンツ階層を利用したドリルダウン選択
```

を採用する。

---

## 14. 最終原則

> コンテンツはAlumni Coreで管理する。サイトの階層はCoreの構造で決める。トップページはThemeが用意したレイアウトへ、そのコンテンツを選択して配置する。

この原則を維持することで、コンテンツを一度登録すれば、Themeを変更しても同じ情報資産を再利用できる。
