# 部活動情報のタグ運用・名寄せ設計

## 1. 基本方針

部活動について、従来検討していた固定の部活動マスタ管理は採用しない。

高校には現在存在する部活動だけでなく、過去に存在した部活動、同好会、愛好会、統廃合された組織、名称変更された組織などが存在するためである。

一方で完全な自由入力だけにすると、以下のような表記ゆれが蓄積する。

```text
野球
野球部
硬式野球
硬式野球部
軟式野球
軟式野球部
```

したがって本設計では、**入力時は自由度を維持しつつ、管理者が後からタグ一覧を確認・名寄せ・統合できる方式**を採用する。

これは「厳格な部活動マスタ」ではなく、**管理可能なタグ辞書**として扱う。

---

## 2. 母校ニュース

母校ニュースはWordPressのタグを利用して部活動を分類する。

例：

```text
投稿：夏の県大会でベスト8進出
タグ：野球部
```

この投稿は母校ニュース一覧に表示されると同時に、テーマ側で部活動タグを条件に「部活動ニュース」として再表示できる。

部活動ニュース専用の投稿データは作成しない。

```text
1つの投稿
   ├── 母校ニュース
   └── 部活動ニュース（タグ条件で再利用）
```

---

## 3. 卒業生情報

卒業生の所属部活動も固定マスタIDには依存しない。

```text
wp_alumni
   │
   └──< wp_alumni_club_memberships
              └── club_name / club_tag
```

入力時には自由な名称を許可するが、保存後は管理者によるタグ名変更・統合の対象とする。

### 基本項目

| カラム | 型 | 説明 |
|---|---|---|
| id | BIGINT UNSIGNED | PK |
| alumni_id | BIGINT UNSIGNED | 卒業生ID |
| club_name | VARCHAR(150) | 表示用部活動名 |
| start_year | SMALLINT UNSIGNED | 所属開始年 |
| end_year | SMALLINT UNSIGNED | 所属終了年 |
| role | VARCHAR(100) | 部長等 |
| notes | TEXT | 備考 |

将来的な実装ではWordPressタグIDまたは共通タグIDを保持する方式に拡張可能とするが、ユーザーに固定マスタを意識させない。

---

## 4. 管理者用タグ一覧

WordPress管理画面に「部活動タグ管理」を用意する。

ここでは登録された部活動名を一覧表示できる。

例：

| タグ | 使用件数 | 操作 |
|---|---:|---|
| 野球 | 12 | 編集・統合 |
| 野球部 | 83 | 編集・統合 |
| 硬式野球 | 7 | 編集・統合 |
| 硬式野球部 | 31 | 編集・統合 |
| 軟式野球部 | 4 | 編集・統合 |

管理者は、タグ名の変更、不要タグの整理、複数タグの統合を行える。

---

## 5. タグの統合（名寄せ）

例えば、以下の表記が混在している場合。

```text
野球
野球部
```

管理者が「野球部」を正式名称として選択し、統合を実行する。

```text
野球 ─┐
      ├──→ 野球部
野球部 ┘
```

統合後は、旧タグが付与されていた関連データを可能な範囲で新しいタグへ付け替える。

対象は設計上、少なくとも以下を想定する。

```text
・母校ニュース
・卒業生の所属部活動情報
・Alumni Voices等の公開コンテンツ
```

統合後の旧名称は、履歴または別名として保持できる設計を検討する。

---

## 6. 「統合してはいけない」ケース

以下は似た名称でも同一扱いにしない可能性がある。

```text
野球部
硬式野球部
軟式野球部
```

したがって、AIやシステムが自動的に統合することはしない。

管理画面では候補として、類似名称を表示することは可能。

例：

```text
硬式野球部
類似候補：野球部、硬式野球、軟式野球部
```

ただし最終的な名寄せ判断は管理者が行う。

---

## 7. 入力時の運用

Alumni Directory等ではタグ入力UIを採用する。

```text
所属していた部活動

[野球部 ×] [軽音楽部 ×]

+ 追加
```

既存タグは候補として表示する。

```text
「野球」と入力
↓
候補
・野球部
・硬式野球部
・軟式野球部
```

候補から選択すれば表記ゆれを減らせる。

ただし、過去に存在した部活動などのため、新しい名称の入力も許可する。

---

## 8. 設計上の位置づけ

部活動は固定された「学校マスタ」ではない。

一方で完全放置の自由入力でもない。

```text
自由入力
   ↓
タグとして蓄積
   ↓
既存タグ候補を表示
   ↓
管理者が一覧確認
   ↓
必要に応じて名称変更・名寄せ・統合
```

という運用を採用する。

これにより、学校の長い歴史に対応する柔軟性と、検索・メール配信・ニュース分類に必要なデータ品質を両立する。

---

## 9. 設計原則

部活動情報は、最初から完璧に整理されたマスタを作るのではなく、実際の利用を通じて情報を蓄積し、必要なときだけ管理者が整理できる仕組みとする。

**入力者には自由度を、管理者には整理する権限を与える。**
