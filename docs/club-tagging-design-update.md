# 部活動情報のタグ運用への設計変更

## 1. 変更概要

部活動について、従来検討していた独自の部活動マスタ管理は採用しない。

理由は、高校には現在存在する部活動だけでなく、過去に存在した部活動、同好会、愛好会、統廃合された組織、名称変更された組織などが存在するためである。これらを厳格なマスタとして維持することは、同窓会広報担当・名簿担当の運用負荷を増やす。

本プロダクトの設計原則である「広報担当が楽をしてホームページを活性化させる」に従い、部活動は固定マスタではなく柔軟なタグ／名称情報として扱う。

---

## 2. 母校ニュース

母校ニュースは通常のWordPress投稿または専用投稿タイプで管理し、部活動に関する記事にはWordPressのタグを付与する。

例：

```text
投稿：夏の県大会でベスト8進出
タグ：野球部
```

この投稿は、母校ニュース一覧に通常表示されると同時に、テーマ側で「野球部」タグを持つ投稿として部活動ニュースにも表示できる。

部活動ニュースは独立した投稿データを持たない。

```text
1つの投稿
   ├── 母校ニュース
   └── 部活動ニュース（タグ条件で再利用）
```

---

## 3. Alumni Coreの卒業生情報

卒業生の所属部活動も、部活動マスタIDには依存しない。

`wp_alumni_club_memberships` は、部活動名称を直接保持する柔軟な子テーブルとして扱う。

### 推奨構造

```text
wp_alumni
   │
   └──< wp_alumni_club_memberships
              └── club_name
```

### `wp_alumni_club_memberships`

| カラム | 型 | NULL | 説明 |
|---|---|---|---|
| id | BIGINT UNSIGNED | NO | PK |
| alumni_id | BIGINT UNSIGNED | NO | 卒業生ID |
| club_name | VARCHAR(150) | NO | 部活動名・同好会名等 |
| start_year | SMALLINT UNSIGNED | YES | 所属開始年 |
| end_year | SMALLINT UNSIGNED | YES | 所属終了年 |
| role | VARCHAR(100) | YES | 部長等 |
| notes | TEXT | YES | 備考 |
| created_at | DATETIME | NO | 作成日時 |
| updated_at | DATETIME | NO | 更新日時 |

### インデックス

```text
PRIMARY KEY (id)
UNIQUE KEY alumni_club_name (alumni_id, club_name)
INDEX alumni_id
INDEX club_name
```

同一人物が同じ名称を重複登録することは防ぐが、異なる人物が同じ名称を登録することは自由とする。

---

## 4. 名簿管理画面

Alumni Directoryの部活動入力は、検索可能な固定マスタのセレクトボックスではなく、複数入力可能なタグ入力UIとする。

例：

```text
所属していた部活動

[野球部 ×] [軽音楽部 ×]

+ 追加
```

過去に登録された名称を候補として表示するオートコンプリートは可能とするが、候補からの選択を必須にしない。

管理者は新しい名称をそのまま入力できる。

これにより、現在は存在しない部活動や当時固有の名称も登録できる。

---

## 5. 検索・メール配信

Alumni DirectoryおよびAlumni Mailでは、部活動名を条件として検索・抽出できる。

例：

```text
club_name = 野球部
```

複数条件も可能とする。

```text
野球部 OR 軽音楽部
```

ただし、表記ゆれは完全自動で統合しない。

例：

```text
野球部
硬式野球部
高校野球部
```

これらを同一視するかどうかは学校ごとに異なるため、MVPでは入力内容を尊重する。

将来必要になった場合のみ、別名・同義語の正規化機能を追加する。

---

## 6. WordPressタグとの関係

母校ニュースのWordPressタグと、卒業生DBの `club_name` は別の保存領域である。

ただし表示・検索の際に名称一致を利用して関連付けることは可能とする。

例：

```text
母校ニュースタグ：野球部
卒業生DB club_name：野球部
```

将来的にテーマ側で、同じ名称を持つ情報をまとめて表示できる。

```text
野球部
├── 現役の母校ニュース
└── 野球部出身卒業生の公開コンテンツ
```

ただしMVPでは、厳格な自動同期や共通マスタ化は行わない。

---

## 7. 旧設計からの変更点

以下は採用しない。

```text
wp_alumni_clubs
club_id
部活動管理専用のWordPress管理メニュー
```

以下を採用する。

```text
wp_alumni_club_memberships.club_name
WordPress投稿タグによる母校ニュースの部活動分類
```

---

## 8. 設計原則

部活動情報は、同窓会システム内で厳格に管理すべき「マスタデータ」ではなく、歴史的な学校コミュニティを表す柔軟な「ラベル情報」と位置付ける。

これにより、過去から現在までの多様な部活動情報を無理なく扱いながら、管理者の入力・維持負荷を最小化する。
