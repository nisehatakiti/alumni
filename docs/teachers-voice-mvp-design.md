# Teacher's Voice MVP設計

## 1. 位置づけ

Teacher's Voice は、教職員から母校の現在や卒業生へのメッセージを投稿してもらい、同窓会サイトに掲載するためのコンテンツである。

本機能は、同窓会の広報担当が自ら記事を探して書く負担を減らすというプロダクトコンセプトに基づく。

ただし、初期段階では教職員名簿を独自DBとして管理しない。

## 2. MVP採用

Teacher's Voice はMVPに含める。

ただし、実際の導入・運用は各同窓会と学校の判断に委ねる。学校側との連携体制や掲載ルールが整わない場合は、機能を有効化せずに利用できる構成とする。

## 3. 投稿内容

以下を主な掲載用途とする。

- 卒業生へのメッセージ
- 現在の学校の様子
- 担当教科・教育活動について
- 部活動について
- 新任時の挨拶
- 退任時のメッセージ
- 印象に残った出来事

投稿内容は自由形式とし、必要に応じて写真を添付できる。

## 4. 基本フロー

```
教職員本人 または 学校担当者
        ↓
Teacher's Voice 投稿フォーム
        ↓
WordPress 下書き
        ↓
同窓会広報担当または管理者が確認
        ↓
公開
```

投稿者が直接公開することはMVPでは行わない。

## 5. データ設計

MVPでは専用の教職員DBを作成しない。

Teacher's Voice は WordPress の投稿またはカスタム投稿タイプとして管理する。

投稿フォームでは最低限、以下を取得する。

- 表示名
- 所属・担当（任意）
- メッセージ本文
- 写真（任意）
- 連絡用メールアドレス（非公開）
- 掲載時の名前表示可否

## 6. 学校側との情報取り扱い

本機能は、学校が公開を認めた情報のみ掲載する運用を基本とする。

同窓会側が独自に新任・離任情報を収集し、事実確認なしに掲載することは想定しない。

## 7. Alumni Voicesとの共通化

将来的には Alumni Voices と投稿受付・下書き生成・管理者承認などの処理を共通化できるよう設計する。

概念的には、以下の Voice 系投稿機能の一つとする。

```
Voice Platform
├── Alumni Voices
└── Teacher's Voice
```

ただし、MVPでは必要以上の共通基盤を先に作らず、共通化できる構造を意識して実装する。

## 8. 設計原則との関係

Teacher's Voice の目的は、教職員管理システムを作ることではない。

**学校や教職員から自然に情報を集め、広報担当は確認・編集・公開に集中できるようにすること**が目的である。
