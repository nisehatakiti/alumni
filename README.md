# 高校同窓会サイト / Alumni WordPress Project

高校同窓会組織向けのWordPressテーマ＋プラグイン企画。

## プロジェクトの方向性

古い「お知らせを並べるだけ」の同窓会サイトを、現代的で更新しやすく、卒業生・在校生・学校をゆるくつなぐWebサイトへ再設計する。

最初は**高校同窓会に特化**して企画・試作する。将来的な大学同窓会・OB会等への展開は、初期設計を壊さない範囲で考慮する。

## 基本方針

- **データ・機能とテーマの表示を分離**する
  - テーマ：見た目、レイアウト、各コンテンツの配置、ブランド表現
  - プラグイン：データ、投稿フロー、承認、連絡先管理、自動処理など
- WordPressを基盤として、用途別テーマと再利用可能なプラグインを組み合わせる。
- 架空の高校「**偽秦高等学校**」をデモ校として、実際のサイトを作りながら仕様を固める。

## デモ校

**偽秦高等学校 同窓会**

コンセプト例：
> つながる。語る。次の世代へ。

## コンテンツとデータ構造

### 会長挨拶【独立投稿】
- 会長氏名
- 役職名
- 挨拶本文
- 写真
- 更新日

### 母校校長挨拶【独立投稿】
- 校長氏名
- 役職名
- 挨拶本文
- 写真
- 更新日

### 沿革【専用フォーム / 専用データ】
入力項目：
- 年月
- 事柄

同じ沿革データをテーマ側でタイムライン・年表などとして表示できるようにする。

### 校歌【専用フォーム】
登録項目：
- 校歌のタイトル
- 歌詞
- 音源
- 楽譜

音源・楽譜はWordPressメディアライブラリから登録できる形を想定する。

### 卒業期早見表【自動生成機能】
生まれ年から、卒業年度と何期生かを確認できる機能。

初期設定として、少なくとも以下を設定する。
- 第1期生の卒業年
- 第1期生の基準となる生まれ年

現在年を基準に一覧を自動生成し、毎年新しい年度が自動的に追加される。新しい年を上に表示する。

### 卒業生インタビュー【独立プラグイン機能】
卒業生からの声はテーマ必須機能ではなく、プラグインを有効化した場合に利用できる機能とする。

#### WordPress標準投稿として管理
卒業生インタビューの記事そのものは、WordPressの通常の投稿フローを利用する。

公開用の記事データはWordPress側で管理する。

- タイトル
- 本文
- 公開名
- 卒業年など公開する属性
- 写真
- 公開状態

投稿フォームから送信された内容は、WordPress上では**下書きまたは審査待ちの投稿**として作成する。

1. 卒業生が公開フォームから投稿
2. WordPressに下書き / 審査待ち投稿を作成
3. 管理者が本人確認・内容確認
4. 管理者が通常のWordPress編集画面で編集
5. 管理者が公開

#### 個人情報・連絡先はプラグイン独自DBで管理
メールアドレス、本名などの管理用情報は、公開記事と分離してプラグイン専用のDBテーブルで管理する。

例：`wp_alumni_interview_contacts`

主な項目：
- id
- post_id（WordPress投稿ID）
- email
- real_name
- graduation_year
- class_name
- club
- verification_status
- submitted_at
- published_at
- last_confirmed_at
- next_confirmation_at
- status
- created_at
- updated_at

`post_id` により、WordPress投稿と独自DB上の管理情報を紐付ける。

#### 写真
写真は任意とする。写真がある場合とない場合で、テーマ側がレイアウトを調整できるようにする。

#### 年1回の掲載確認と自動メール
独自DB側で投稿日・公開日・最終確認日・次回確認日を管理する。

例：
- 公開日：2026-08-27
- 次回確認日：2027-08-27

定期処理により `next_confirmation_at` が到来した投稿者を検索し、掲載内容の確認メールを自動送信する。

メール例：
- このまま掲載する
- 内容を更新する
- 掲載を終了する

送信後は、次回確認日や送信状態を更新する。

#### メール送信履歴
必要に応じてメール送信履歴も独自DBで管理する。

例：`wp_alumni_interview_mail_log`

- id
- contact_id
- mail_type
- sent_at
- status

将来的には未回答者へのリマインド送信にも対応できる設計とする。

#### 定期実行
定期確認処理はWP-Cronに対応する。

ただしアクセスが少ない同窓会サイトでも確実に動作させるため、運用環境ではサーバー側CRONからWordPressの定期処理を起動する方式を推奨する。

### イベント情報【専用投稿】
最低限の入力項目：
- 日付
- タイトル
- 内容

### お知らせ【専用投稿】
入力項目：
- タイトル
- 自由形式の本文
- 公開日

### 新着情報【統合表示】
イベント情報とお知らせを、それぞれ別に管理しつつ、トップページ等では「新着情報」として日付順に統合表示する。

## トップページ構成

### ヘッダー / ブランド表示
- 学校の校章
- 同窓会独自のロゴ（存在する場合）
- 「○○高等学校同窓会」の名称

基本イメージ：
`[ 校章 ]   偽秦高等学校同窓会   [ 同窓会ロゴ ]`

### トップページ全体メッセージ【自由入力欄】
トップページには、管理者が自由に入力できる**全体メッセージ欄**を設ける。

### 基本セクション
テーマ側で各コンテンツの配置と見せ方を決める。

基本デモテーマでは以下を想定する。
1. ヘッダー / 校章・同窓会ロゴ・同窓会名称
2. 全体メッセージ（自由入力）
3. 新着情報（イベント＋お知らせの統合）
4. 同窓会会長挨拶
5. 母校校長挨拶
6. 母校ニュース
7. 同窓会ニュース
8. 沿革
9. 卒業生からの声（プラグイン有効時のみ表示）

コンテンツそのものは配置情報を持たず、テーマ変更によって表示順やレイアウトを変更できるようにする。

## メールマガジン構想

- Web記事をメールマガジンで案内
- 新着情報、活動報告、総会案内、母校NEWS等を配信
- 「一度記事を書けばサイト＋メールで利用できる」更新導線を目指す
